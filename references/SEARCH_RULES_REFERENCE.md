## 3. 各来源最值得保留的差异

### 3.1 百度：普通结果、特殊卡片与网盘补采

**采集要点：** 百度结果可分两组检查：普通结果容器中的 `tpl='ai_agent_distribute'` 排除条件，以及 `div.cosc-card-content` 特殊卡片。特殊卡片可检查 `snapshotUrl`、`agentId32`、`agentName` 的提取，并补充检查文件模块、`ai_agent_distribute` 模块及含百度网盘地址的链接。适用结构、提取作用域和结果对应关系需在当前页面验证。

`snapshotUrl` 的提取线索是最近的带 `mu` 属性的元素，其值为 URL 而非截图；`agentId32` 对应链接参数 `agentid`，`agentName` 对应同名链接参数，不能改写成普通 HTML 属性提取。字段名包含“32”并不证明其长度或用途已校验，当前实现须按实际参数验证。

**实现参考：** 作者关注“搜索中出现智能体文包”时，应考虑普通标题以外的结果类型，并保留搜索页、卡片、落地页／分享链接与公开元数据之间的对应关系。上述线索不证明补采作用域、去重与绑定已经正确，本包也不提供智能体内部对话接口；不要把“找到一个网盘链接”写成“已经核验分享内容”。

### 3.2 夸克：页面变体、滚动与搜索现场

**页面特征与采集要点：** 夸克桌面和移动页面均可检查 `qk` 卡片，但标题、摘要候选及取链方法需分别适配。桌面侧可检查滚动等待和“没有更多内容了”的结束信号，并在第一页渲染后保存 `screenshot_quark_search` 与 `quarkSearchUrl`；移动侧没有在本文定义相同的截图步骤。上述行为需验证当前页面后实现。

**实现参考：** 不要把“两个入口”计成两份独立索引，也不要把桌面解析器未经检查就套到移动页面。是否需要两个入口，由作者需求决定；页面变体不是在受限后切换身份继续请求的手段。需要后续投诉材料时，可在搜索阶段保存对应页面现场，详见第 6 节。

### 3.3 Bing、wkbrowser、360：目标地址不一定在第一个链接里

**取链方式：** Bing 可检查标题链接 `u` 参数中的 `a1` 前缀与 Base64 内容，同时检查标题 `href`；wkbrowser 可检查 `data-log-extra` 或 `cr-params` 结构化属性中的 `h5_url`；360 可检查标题属性 `data-mdurl` 与标题 `href`。各提取路径的适用条件与结果需在当前页面验证。

**实现参考：** 保留“包装地址、字段中记录的目标、展示文字”之间的区别。解析属性和参数是数据处理，不是执行其中代码。本文未定义所有解码、回退和异常行为；无法可靠取得目标时，保留未解决状态，不编造完整 URL。不要因为标题正确，就默认随手取得的第一个链接也是对应目标。

### 3.4 搜狗普通搜索与微信文章搜索：两条发现路径

**采集要点：** 普通搜狗可检查标题、摘要及三种取链线索：容器 `dataUrl`、展示地址文字 `citeText`、标题 `href`，并补充检查微信文章链接。`weixinsearch` 是独立的微信文章搜索入口，可检查文章列表、标题、链接和下一页。具体结构及推进方式需在当前页面验证。

**实现参考：** 需要公众号线索时，分别考虑“普通搜索里的公众号文章”和“专门的微信文章搜索”。展示地址可能不是已确认的完整目标，不能仅补上协议就当成可靠 URL。本文未提供文章正文解析和正文内分享链接的继续提取；若当前作者需要这些，应作为本项目新增能力另行实现和说明。不要从这两条采集路径外推出微信私聊、群消息或全量公众号检索。

### 3.5 神马：同页多种结果卡片

**采集要点：** 神马页面可分别检查 `sc` 与 `qk-card` 两类结果的标题、摘要和取链方式，并检查“下一页”入口。两类结果的实际结构及分页行为需在当前页面验证。

**实现参考：** 一页里两种卡片不能只解析其中一种却宣称全部处理；同一内容跨卡片重复出现时，怎样去重、怎样保留发现来源由当前项目决定。`dataUrl` 的完整读取与处理行为仍需当前实现明确。

## 5. 跨来源的取链、分页与失败处理

**分页与参数参考：** 取链方法可区分为 `attr`、`href`、`dataUrl`、`base64param`、`jsonUrlParam`、`citeText` 六类线索；各标识的执行含义需明确。分页可采用点击、滚动、URL 三种方式；页面加载、翻页、切换来源分别考虑等待条件。页数参考值为八项引擎的 `maxPages` 取 8、微信文章取 5；这些仅为可选参数，不是新软件的必选值。检测应考虑验证码、登录、限流和反自动化相关标记，遇到需要本人验证的情况提示在窗口内处理。

**未提供的实现：** 本包没有说明完整的结果合并算法、HTTP 429／Retry-After 执行处理，也没有通用的“正常零结果、JS 壳、解析失效”区分算法。仅看到检测字段存在，不能宣称这些情况都已可靠处理。

**实现参考：** 为实际选择的来源实现能运行的取链和推进方式，保留本轮实际查询、翻页／滚动范围、受阻和未执行部分；预算、速率和失败退让按当前需求决定，不强制八页或固定延迟。技术失败应显示结果未知，而不是没有盗文；具体状态名、保存结构与界面不强制。已有业务判断和失败记录见 [业务指南](ANTIPIRACY_BUSINESS_GUIDE.md) 与 [经验索引](LESSONS_FOR_AGENT.md)，不在这里重复制定一套测试协议。
